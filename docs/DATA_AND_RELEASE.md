# Data, provenance and release checklist

**Public distribution, November 2, 2026:** the repository is
https://github.com/paulhbeaumont/invariance-replication. Code is in Git; prepared
data and exact USAspending archives are release `v1.0.0` attachments, retrieved
and checksum-verified by `download_data.py`. See [PUBLIC_RELEASE.md](PUBLIC_RELEASE.md)
for attribution and the release boundary. The local-review checklist below is
retained as development history, not a statement that hosting is still pending.

## Included data

| Directory | Contents and role |
| --- | --- |
| `data/upstream/baseline_roll5_gap5/` | Prepared real annual net procurement and consistent-county panel. Used to rebuild county spending, outcomes and the IV. |
| `data/upstream/naics6_annual/` | Reconciled annual county-industry employment, 1978–2016; checked against county employment totals. |
| `data/upstream/naics4_characteristics/` | Allocated NAICS4 employment in 1978/2000, underlying the characteristic construction. |
| `data/disaggregation/` | County frames and sufficient statistics for exact no-industry-year-FE cell estimates and the decomposition. |
| `data/cells/` | Full h = 3 log and midpoint cell data for the two industry-year-FE regressions. The log file exceeds GitHub's ordinary file-size limit. |
| `data/aggregation/` | Frozen county and regional regression inputs for each specification in the draft. |
| `data/heterogeneity/` | Prepared county/state interactions and fixed-year characteristics; original and income-winsorized 1978 characteristics are also retained. |
| `reference/` | Independent saved numerical benchmarks and paper exhibits, not generated by the new launcher. |
| `provenance/` | SHA-256 input/function manifests and unchanged original construction/estimation code. |
| `data/raw/USAspending/production/` | Exact 12 FY2007-2018 DoD Award Data Archive ZIPs dated August 6, 2026, plus original receipts. |
| `data/raw/USAspending/diagnostics/` | Six FY2001-2006 bulk-download overlap ZIPs, original request payloads/responses and receipt; diagnostic only. |

The prepared-data launcher's input manifest gives the original **project-relative** source of every staged input. There are no runtime imports from the original project. Archived source files can contain historical absolute paths; they are not executed by that launcher. The prepared county inputs remain constructed snapshots. The separate raw extension now also contains the exact USAspending archives, verified by its own manifest and `verify-usaspending` command; this does not replace the older 184-file input manifest.

Useful columns: `ccg` is consistent county-group ID; `unit` is regional ID; `year` is outcome endpoint; `E/E_b` and `P/P_b` are current/baseline employment and population; `x/z` are county spending and instrument; `x_agg/z_agg` are regional exposure and instrument; `weight` in aggregation is the county's lagged regional employment share. `log_y`, `std_y`, `y` or `y_mpgr` identify the preserved log, standard and midpoint outcomes. Cell `w_lag` and `w_mpgr` are the corresponding local-industry shares. Characteristic `C_` columns are standardized 2000 values and `old_` columns standardized 1978 values; heterogeneity interactions use the original prepared 1978 definitions.

## Explicit limitations

The October 28 staged clean run **reconstructs all current paper inputs and
reproduces the reported results** from the declared external sources. The
94-file application build, 96 independent input comparisons, all models and
422 final numeric checks pass; the refreshed PDF was visually inspected. See
`FULL_RAW_VERIFICATION_2026-10-28.md` for numerical differences and limitations.
`raw_to_results.py` is the complete raw-chain entry point; `raw_rebuild.py`
retains the separate source/recovery tools. Downloaded raw files are gitignored
and are not automatically cleared for redistribution.

The prepared-data entry point re-estimates every displayed model from included
regression inputs and rebuilds the county frame from annual working sources.
It does not itself parse raw military contracts. The separately verified raw
workflow does, then reconstructs the application before estimation. The
published harmonized EFSY panel remains an external input in both workflows;
neither independently reconstructs its authors' original Census imputation.
Do not describe `replicate.py all` as the raw-chain command.

The USAspending bundle contains 18 unchanged ZIPs (9,359,636,428 bytes) and nine
original metadata files. The source refreshes its archives, so new downloads
are a newer vintage, not exact replacements. Public deposition is separately
pending; see [USASPENDING_ARCHIVES.md](USASPENDING_ARCHIVES.md). ZIPs are present
locally but excluded from ordinary Git tracking; a Git-only export is not a
complete raw-data distribution.

A nonzero aggregation identity residual is part of the preserved specification, not an error to remove. The sample and rounding remainder in the coefficient decomposition are retained numerically. Neither residual is altered to improve the exhibits.

## Before a public GitHub release

1. Obtain author approval of the package and the exact paper version it accompanies.
2. Check redistribution and attribution requirements separately for military procurement, county employment/industry allocation, population, income and geography. Public origin alone does not establish redistribution permission for every constructed file.
3. Choose the raw/prepared data assets to deposit and document their verified source boundary. A Git-only checkout without the raw archive assets is not a complete raw-data release.
4. Audit archived code/configuration for personal paths and historical project references. They are not credentials, but should be reviewed before publication. Choose licenses for author-owned code; do not assign an invented blanket license to source data or vendored third-party code.
5. Install Git LFS and check that every Parquet file is a pointer before the initial push, or use checksummed release assets with an explicit downloader. The local bundle intentionally contains actual data, not placeholders. Check hosting/storage quotas first.
6. Run `replicate.py all` in a clean, relocated checkout using only bundled inputs, preserve its logs and `output/replication_check.json`, and compare to the independent frozen references.
7. Add the repository URL to the paper only after the public release exists. No GitHub account actions or uploads have been performed here.

The figure renderer vendors `coefplot.ado` from the existing Stata installation (Ben Jann's package) solely to make plotting self-contained. Preserve its attribution header and review its distribution terms before publishing.
